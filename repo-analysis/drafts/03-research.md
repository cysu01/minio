# MinIO 调研笔记

## 项目解决的核心问题

**场景 1 - 云原生私有存储**：企业需要 S3 兼容的对象存储，但不愿依赖 AWS。传统方案 Ceph 运维复杂度极高（CRUSH map、PG management、多服务协调），MinIO 用单二进制解决了这个问题。

**场景 2 - AI/ML 数据湖**：PyTorch/TensorFlow 训练需要从高吞吐存储中读取 TB 级数据集。MinIO 专为这类大对象流式读写优化，官方宣称 PUT 吞吐可达 325 GiB/s，GET 达 400 GiB/s（NVMe 集群）。

**场景 3 - 边缘/混合云**：单节点部署到多 region 站点复制，同一套 API，无缝扩展。

## 竞品定位对比

| 项目 | 定位 | 优势 | 劣势 |
|------|------|------|------|
| MinIO | 高性能 S3 专用 | 性能最优、S3 兼容性最好（382测试通过）、运维简单 | 仅对象存储、AGPL 许可证 |
| Ceph RGW | 统一存储（块+文件+对象）| 生态成熟、企业级特性 | 运维极复杂、性能低于 MinIO |
| SeaweedFS | 小文件高效存储 | 小文件 IO 优秀、主从架构简单 | S3 兼容性差（仅56测试通过）|
| Garage | 边缘轻量存储 | 极小内存占用、地理分布 | 功能不完整 |
| RustFS | Rust 重写的 MinIO 替代 | 内存安全、性能潜力 | 尚不成熟 |

## 独特价值主张

1. **专一性**：只做对象存储，不做块存储和文件存储，因此在对象存储这一维度上性能碾压 Ceph
2. **运维极简**：单二进制部署，无外部依赖，所有节点对等（无 Master 节点），启动后自动协商
3. **S3 原生**：不是"兼容"S3，而是重新实现了 S3 协议的每一个细节，包括 multipart、select、object lock
4. **纠删码对象级**：与其他系统的卷级 EC 不同，MinIO 在对象级别做 EC，允许每个对象独立设置存储类别
